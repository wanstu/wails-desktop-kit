# 升级兼容与本地开发范围

[返回首页](../README.md) · [升级说明](runtime-hardening.md)

## 使用方是否需要修改源码

Kit 的默认演进目标是保持已公开的常规用法兼容。内部线程、资源清理和校验修复通常不要求业务改代码；新增能力通过可选字段或小接口提供。需要修改源码或改变行为的升级必须单独列明。

v0.2.0 的常规 Config／TrayItem／Manager 传值方式可继续使用。AutoStart 字段读取的具体类型假设，以及旧的退出／隐藏／FS 用法，需要按升级说明核对。FRP 的 HideSafe 调整属于产品策略选择。

## 将可控开发文件集中在 D:\projects

本地项目源码、worktree、脚本、构建输出和可配置缓存可放在项目目录下。尽量直接调用 git、go、gh 等可执行程序；复杂步骤写成可审查的脚本文件，再用 -File 执行。

Go 本地构建可在当前进程设置 GOTMPDIR、GOCACHE、GOMODCACHE 到项目下的专用目录，避免新下载和编译缓存散落到用户目录。设置仅用于本次构建，不覆盖用户的全局 Go 配置。

这不构成文件系统沙箱。系统 PowerShell、Git、Go 工具链、凭据存储、WebView2 与操作系统仍可能访问其他目录；应用的正常配置和登录自启也有平台约定位置。

安全软件弹窗需按实际进程、命令和文件判断。将项目目录加入信任区不能保证系统 PowerShell 的行为规则不再触发；不应为解决一次开发提示而整体信任系统 PowerShell 或关闭防护。
